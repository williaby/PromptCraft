## Tier 1: Blocking Issues

These block verification of any other work; resolve first.

### 1. Pydantic v1/v2 interpreter leak

**Symptom:** `make test-fast` fails at import with:

```text
ImportError: cannot import name 'field_validator' from 'pydantic'
(/usr/lib/python3/dist-packages/pydantic/...)
```

**Root cause:** `poetry run pytest` is resolving the `pydantic` import
from the system Python 3.12 site-packages instead of the Poetry venv's
Python 3.11 with Pydantic v2.

**Fix:** Re-point Poetry's venv at the correct interpreter and
reinstall:

```bash
poetry env use python3.11
poetry install --sync
poetry run python -c "import pydantic; print(pydantic.__version__)"
```

**Definition of done:** `make test-fast` runs to completion; verified
at both `HEAD~1` and current `HEAD` to confirm it reproduces across
recent commits.

## Tier 2: Functional Cleanup

### 4. Convert Category 3b commands to skills

Sixteen project-specific slash commands remain under `.claude/commands/`
that encode PromptCraft-specific knowledge. Global equivalents do not
exist, so they should be converted to skills (not deleted). Skills
auto-activate via trigger keywords, whereas commands require explicit
invocation; converting improves discoverability.

**Commands to convert:**

- `creation-agent-skeleton`
- `creation-knowledge-file`
- `function-loading-control`
- `migration-knowledge-file`
- `migration-legacy-knowledge`
- `migration-qdrant-schema`
- `quality-frontmatter-validate`
- `quality-naming-conventions`
- `tools-ai-validate`
- `validation-agent-structure`
- `validation-frontmatter`
- `validation-knowledge-chunk`
- `validation-naming-conventions`
- `validation-standardize-planning-doc`
- `workflow-resolve-issue`
- `workflow-review-cycle` (also needs item 5 below)

**Method:** Use the global `skill-creator` skill. Each conversion:

1. Extract the command body into a skill at `.claude/skills/{name}/SKILL.md`.
2. Add YAML frontmatter with `description` field containing trigger
   keywords.
3. Delete the original `.claude/commands/{name}.md`.
4. Update any cross-references in other commands or docs.

Consider consolidating overlapping pairs:

- `quality-naming-conventions` + `validation-naming-conventions`
- `quality-frontmatter-validate` + `validation-frontmatter`

## Tier 3: Architectural Decisions

### 7. Execute BasedPyright migration

Four-phase plan exists at [`basedpyright-migration.md`](basedpyright-migration.md).

Current state: MyPy is the type checker; `pyproject.toml` has MyPy in
strict-ish config with `disallow_untyped_defs` and

Execute Phases 1-4 in order; each has its own exit criteria.

### 8. Runtime `zen_client/` refactor

`src/mcp_integration/zen_client/` is application code (not developer
tooling) that `src/ui/journeys/journey2_intelligent_search.py` depends
on for Journey 2's intelligent search feature. The global MCP
configuration does not serve the PromptCraft application runtime; it
only serves Claude Code sessions.

**Options:**

- **X:** Keep `ZenStdioMCPClient` indefinitely. PromptCraft legitimately
  needs a runtime MCP client; the Zen branding is incidental.
- **Y:** Replace with the upstream `mcp` Python SDK. Removes the
  Zen-specific naming; requires reworking `connection_bridge.py`,
  `zen_stdio_client.py`, and the test files under
  `tests/unit/mcp_integration/zen_client/`.
- **Z:** Factor the Zen-specific bits out so the runtime client is
  provider-agnostic. Middle ground; reduces rewrite scope while
  decoupling from the Zen fork.

Decision should involve the product owner since it affects Journey 2.

### 9. Contract and performance tests

`tests/contract/` (5 files) and `tests/performance/{locustfile,
performance_config}.py` exercise MCP contracts against a running Zen
server. With Zen MCP moved to the global layer, these tests need a
decision:

- **Delete:** Fastest. Loses active contract coverage.
- **Rework:** Point at a locally-launched MCP server for test runs
  (keeps coverage, moderate rewrite).
- **Skip with tracking issue:** Middle ground. Mark `@pytest.mark.skip`
  with a reason, file an issue, decide later.

### 10. Context7 MCP placement

`.mcp/servers/optional.json` declares a project-level Context7 MCP
server. If Context7 is used across multiple projects, consider moving
to the global MCP config. If it is genuinely project-specific, leave

### 12. RAD tag expansion

Only 2 `#CRITICAL`/`#ASSUME`/`#EDGE`/`#VERIFY` tags exist in `src/` as
of 2026-04-20. Global expects tags in all mandatory categories:

- Timing dependencies
- External resource calls
- Data integrity boundaries
- Concurrency primitives
- Security-sensitive paths
- Payment or financial logic

**Priority tagging candidates:**

- `src/utils/encryption.py` (security)
- `src/auth/`, `src/auth_simple/` (security + data integrity)
- `src/core/` HyDE processor (external model calls)
- `src/mcp_integration/` (external resource calls, concurrency)
- `src/api/` endpoints handling user-submitted content (security)
- `src/database/` (data integrity)

Pair each tag with a `#VERIFY` instruction per the RAD methodology.
